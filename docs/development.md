# 개발·검증 기록

## 범위와 실행 방식

2026-10-20 착수 시 문서 4개만 있었고 Git 저장소·앱·테스트는 없었습니다. 원본 명세와 사용자 파일을 보존하고 필요한 파일만 추가했습니다. Git 초기화·커밋·푸시·배포는 수행하지 않았습니다.

사용자의 명시적인 subagent 분할 요청에 따라 루트 에이전트가 관제했습니다. 코어 작업자는 타입→규칙→reducer→콘텐츠→저장, 데스크톱 작업자는 창·탐색기·뷰어, 앱 작업자는 Provider·조사·제출·엔딩·저장/접근성 E2E를 담당했습니다. 루트는 실행 기반·공유 계약·완주 E2E·문서·통합 검증을 맡았습니다. 타입 계약 이후 구현을 병행하고 최종 검증은 통합했습니다. 계획에 있는 기본 단일 실행 방식 대신 이번 요청을 적용했습니다.

- 확인 환경: Windows, Node.js 24.18.1, npm 11.16.0. 프로젝트 지원 하한은 Node.js 22.12입니다.
- lockfile 설치 결과: React/ReactDOM 19.3.1, Vite 7.3.7, TypeScript 5.9.3, Vitest 4.1.12, Playwright 1.64.1.
- [Vite 공식 요구사항](https://vite.dev/guide/), [Vitest 공식 마이그레이션 요구사항](https://vitest.dev/guide/migration.html), [Playwright 공식 실행 환경](https://playwright.dev/docs/intro)을 조회했습니다. npm 메타데이터의 engines도 확인했습니다. 최신 메이저로의 불필요한 전환 없이 호환 범위를 선택했습니다.
- 최초 `npm.cmd install`로 lockfile 생성, `npm.cmd ci` 재현 설치 성공. 모든 lockfile 다운로드 출처는 `registry.npmjs.org`입니다.

- 설치 중 tinyexec 및 Playwright package.json 누락으로 실행기가 시작하지 못했습니다. npm ci와 Playwright 동일 버전 재설치 후 정상화했습니다. OneDrive 상위 경로 접근에 대한 샌드박스 제한은 승격 실행으로 검증했습니다.

## 보안·접근성 확인과 한계

소스·dist 40개 파일의 비밀키 형태와 공개 환경파일을 검사해 탐지 0건을 확인했습니다. 정규식 점검은 모든 비밀정보의 부재를 증명하지 않습니다. 소스에서 localStorage 접근은 save-adapter.ts 한 곳이며 HTML 주입·문자열 코드 실행·전체 저장소 삭제 API는 사용하지 않습니다. 정적 SVG 존재 및 스크립트·이벤트·외부 리소스 미포함은 콘텐츠 검사에 포함합니다.

저장 원문과 사용자 입력을 로그로 출력하지 않습니다. React 텍스트 렌더링과 textarea를 사용합니다. HTML/스크립트 형태 메모가 저장·복원 후에도 실행되지 않는 브라우저 검사를 통과했습니다. 변조 저장·잠금 우회·초과 길이·중복·잘못된 참조를 거절하는 단위검사와 저장소 차단/용량 초과를 주입하는 브라우저 검사를 구분합니다. 자동 검사 통과가 전체 보안을 보장하지는 않습니다.

정답과 콘텐츠는 정적 번들에 포함됩니다. 잠금은 게임 규칙이며 인증·암호화가 아닙니다. 실제 외부 서버나 계정은 없습니다. 향후 정적 배포 시 호스팅에서 CSP와 `X-Content-Type-Options: nosniff`, Referrer-Policy 등을 검토해야 합니다. CSP는 로컬 스크립트·스타일, React 창 배치용 인라인 스타일, SVG data URL을 고려해야 하며 개발 서버 설정은 운영 보안 헤더를 대신하지 않습니다. 배포하지 않았으므로 호스팅 헤더 적용은 미검증입니다.

초기 실행기 설치가 지연되는 동안 테스트 작성 후 구현이 진행되어, 계획의 모든 항목에서 **구현 전 의도된 실패 확인**을 수행하지는 못했습니다. 해당 체크박스는 미완료로 남깁니다. 구현 후 통과를 과거의 red 증거로 대체하지 않습니다.

Chromium 외 브라우저, 스크린리더, 실제 초회 사용자 플레이테스트는 수행하지 않았습니다. 15~30분과 난이도·재미는 미검증 목표입니다.
